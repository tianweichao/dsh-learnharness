# 06 · 出题工艺

这一篇是**仪器**：怎么把一道题写得能测出真实理解，而不是测出"他会不会猜你想听什么"。

## 承诺机制：为什么必须先写答案键

模型有一个稳定的失败模式：**看到学生的答案之后，会把错的说成"其实也说得通"。**

这不是恶意，是语言模型的自然倾向——它总是倾向于认可眼前的东西。

解法是**在出题之前就把答案键写死**，然后判分时只能照着它判：

```bash
node ~/.dsh/skills/learnharness/scripts/lh.mjs commit <<'JSON'
{"kind":"quiz","type":"check","nodeId":"qkv",
 "question":"如果 Q/K/V 共用一个投影矩阵，会失去什么？",
 "options":[…],
 "correctAnswer":"asym",
 "explanation":"query 与 key 是两种角色；共享投影会让相似度退化成对称的自身比较。"}
JSON
```

承诺之后**绝不修改**。学生坚持自己是对的，也不改判——只解释为什么不是。

`explanation` 也要在出题时写，理由一样：**事后再写解释，解释会被学生的答案塑形。**

## 选项怎么写

| 规则 | 原因 |
|---|---|
| 2–4 个选项 | 2 个太容易猜（50%），5 个以上开始考阅读 |
| **裸断言**，不带修饰 | "点积会变成负数"而不是"在数学上，点积可能会变成负数" |
| 正确选项**改写成干扰项风格** | 正确项如果更细/更长/更谨慎，等于给了答案 |
| 干扰项必须是**真实可能犯的错** | 用他探针阶段的 misconception 做干扰项最好 |
| 不加 `description` | 描述会泄露正确性 |
| 不用"以上都对" | 排除法就能做对，测不到知识 |
| 选项长度接近 | 长度是最大的泄露信号 |

**最好的干扰项**是"看起来像正确推理但差一步"的那种。次好的是"常见误解"。最差的是"明显荒谬"。

## 多选

只有真的需要多选时才多选，并且必须 `multiSelect: true`（脚本会拒）。

多选的风险：学生可以用"少选一个"来对冲不确定性。所以多选题目要设计成**少选即错**，并在题面说清"选出全部正确的"。

## 置信度：第二个问题

`ask_user_question` 支持一次问多个问题。置信度作为第二个问题：

```
Q1: [题目]
Q2: 你有多确定？ 0 / 30 / 50 / 70 / 90 / 100
```

规则：

- **只在真作答时问。** 选"我不知道"时不问（没有意义，且会鼓励伪装）。
- 默认值给 50（真正的五五开），不要给 100。
- 解读：
  - **答对 + 高置信** = 真会
  - **答对 + 低置信** = 猜的，等于不会
  - **答错 + 高置信** = 最危险，必须优先修
  - **答错 + 低置信** = 正常的知识缺口

## 自由回忆题（explain）

不给选项，让他自己写完整答案。**你必须在出题前提交完整答案**（`correctAnswer` 就是那个完整答案，含推理）。

判分时严格对照承诺的答案：

- 他说的和承诺答案的核心推理一致 → 过
- 结论对但推理缺步 → 不过，指出缺哪步
- 用了不同但同样正确的路径 → **过**，并且说明"你的路径和我的不同但成立"（这是最该奖励的情况）

**自由文本绝不用规则判分**（关键词匹配会误判），必须由你读他的思路来判断。

## 判分之后怎么说话

| 情况 | 说什么 |
|---|---|
| 对 + 思路正 | 一句"对"，进下一步。不要夸 |
| 对 + 思路歪 | "答案对，但你的理由不对——你是从 X 推的，正确的理由是 Y。这种情况下换一道你就错了" |
| 错 + 错得有价值 | 先肯定他推对了哪一段，再定位断点 |
| 错 + 明显缺口 | 直接定位断点，回教学，不在这题上纠缠 |
| 说"我不知道" | 不算错，但**必须记下来**：这条线要重新走一遍 |

**永远不要**：先夸再否定（"很好的尝试！但是……"）、说"很好的问题"、说"你已经很接近了"（除非真的接近且你能指出差在哪）。

## 一轮只问一题

`commit` 会在已有未答题时拒绝——这是刻意的。一次多题会让你无法判断哪一题对应哪一层，也会让学生进入答题模式。

问完 → 等他答 → `answer` → 判分 → 再决定下一题。
