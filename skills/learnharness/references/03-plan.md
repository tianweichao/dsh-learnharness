# 03 · 计划（plan）

计划是**依赖图，不是教学大纲**。它的唯一用途是：让每一轮教学都知道"我们现在在哪、下一步必须是什么"。

## 节点粒度：一个推理步

判断标准：**一个节点 = 学生需要接受的一个新的推理步。**

| 是节点 | 不是节点 |
|---|---|
| "Q/K/V 为什么要三套投影" | "自注意力机制"（太大，含 4–5 个推理步） |
| "点积为什么能表示相似度" | "第 3 章"（那是大纲） |
| "softmax 为什么需要除以 √d" | "练习"（那是活动，不是理解） |

粒度检验：**如果一个节点讲完后你还需要讲两件事才能出检查题，它太大了。**

## 边 = 依赖方向

`a --> b` 表示 **a 是 b 的前置**（a 必须先理解）。

不要画"包含"关系（那是大纲），只画"没有 a 就无法理解 b"。

## 起点和终点

- **起点**：探针得到的 floor。计划必须从学生**已经站的地方**开始，第一个节点要能直接用上他已接受的东西。
- **终点**：用户的学习目标，用一句话表述成一个节点。

如果终点节点离起点太远（中间超过 15 个节点），**把目标拆成两次会话**，而不是把节点做粗。

## 规模：一张地图，不是一门课

5–15 个节点。宁可粗一点再在教学中细化，也不要一开始画 40 个——计划会变，而且 40 个节点会让你忍不住按大纲推进而不是按理解推进。

（LearnHarness 原版在这一点上自相矛盾：工具描述说 5–15，规划提示词说无上限。这里取 5–15，理由是**计划要在教学中被改写**，一开始过细会锁死。）

## 写法

```bash
node ~/.dsh/skills/learnharness/scripts/lh.mjs plan <<'MMD'
flowchart TD
  tok[同一输入的三次投影] --> qkv[Q/K/V 为什么要分开]
  qkv --> dot[点积为什么是相似度]
  dot --> soft[softmax 与 √d 缩放]
  soft --> agg[加权求和得到输出]
  agg --> multi[多头 = 多个子空间]
MMD
```

规则（脚本会带行号报错）：

- 首行必须是 `flowchart TD`（或 `graph TD`）
- 节点 id 只能是小写 slug：`a-z0-9`，用 `-` / `_` 连接
- 不能有环、自环、重复边
- 标题写在 `[方括号]` 里，可以中文、可以有空格

## 计划必须给用户看

画完**不要立刻开始教**。先给用户看这张图，说一句："这是我打算走的路径，你看有没有多余的、缺的、或者顺序不对的。"

用户改了 → 重新 `plan`（整体替换，脚本会保留仍然存在的节点访问记录）。

用户认可 → `phase teach`，开始第一个节点。

## 之后每道题都必须带 nodeId

`commit` 的 `nodeId` 字段是"我们在计划的哪个位置"**唯一可信的来源**。位置不是记在对话里的，是从"最近一道带 nodeId 的题"派生出来的。

所以：

- 出题必须带 `nodeId`
- `nodeId` 必须是计划里存在的（脚本会拒）
- 讲完一个节点用 `visit <nodeId>` 标记

不带的后果：位置感丢失，学生会发现"我们在来回跳"。

## 计划会变，这是正常的

教学中发现某个节点其实是空的（学生会）→ 跳过它。
发现某个节点其实需要拆成三个 → 重新 `plan`，整体替换。
发现起点选错了（floor 判断错）→ 回到探针补一题，然后重画。

**计划是地图，不是合同。** 但每次改动都要让用户看见。
