# 02 · 探针（measure）

探针阶段只回答一个问题：**为了教会他 X，他的理解边界在哪？**

不是全面测评，不是摸底考试。**够画出计划就停。**

## 先拆依赖线（strand）

把目标 X 拆成它真正依赖的几个面。每条 strand 是"如果这块不成立，X 就立不住"的一条线。

以"理解 Transformer 的注意力机制"为例：

| strand | 这条线要成立，需要什么 |
|---|---|
| 为什么需要注意力 | 知道 RNN 的顺序依赖瓶颈 |
| Q/K/V 的角色 | 知道 query 与 key 是两种不同角色 |
| 点积为何是相似度 | 知道内积衡量方向一致程度 |
| softmax 的作用 | 知道它把分数变成竞争性权重 |
| 多头在做什么 | 知道多个子空间并行 |

拆 3–6 条。少于 3 条说明拆得不够；多于 6 条说明在写大纲而不是依赖。

## 二分定位：从高处进入

**不要从最基础问起。** 从"较高处"进入，然后二分：

```
先问一条中高难度的应用题
├─ 答得出、讲得清 → 这条 strand 的 floor 在这里，往下一层再试
└─ 答不出、讲不清 → 这条 strand 的 ceiling 在这里，往上收一格
```

floor = 他能**自己讲清并应用**的最高点。
ceiling = 他开始讲不清的最低点。

floor 和 ceiling 之间的那一格，就是这条线要教的范围。

## 一次只问一道题

问完就停，等他答。不要连发三题。

一次问多题会把学生推回"答题模式"，而且你无法知道哪一题对应哪一层。

## 问应用，不问背诵

| 差 | 好 |
|---|---|
| "softmax 的公式是什么？" | "给定三个注意力分数 [2, 1, 0]，权重大概是多少？" |
| "Q 和 K 有什么区别？" | "如果让 Q 和 K 共用一个投影矩阵，会失去什么？" |
| "什么是多头注意力？" | "为什么要 8 个头而不是 1 个 512 维的头？" |

背诵题测的是检索，应用题测的是结构。探针要的是结构。

## 读三个信号，不只读对错

1. **答案**：对/错/部分对。
2. **置信度**：问一句"你有多确定（0–100）"。**答对但低置信 = 猜的**，等于不会；**答错但高置信 = 最危险的误解**，必须优先修。
3. **思路**：他怎么想的。这是最有价值的信号——思路歪但答案对，比思路正但算错严重得多。

## 记录结构化评估

每条 strand 写四件事：

- **floor**：他能自己讲清到哪
- **ceiling**：从哪开始讲不清
- **misconception**：具体误解是什么（要具体到一句话，不要写"基础不牢"）
- **build from**：计划应该从哪里建起

```bash
node ~/.dsh/skills/learnharness/scripts/lh.mjs strands <<'JSON'
[
  {"strand":"Q/K/V 的角色",
   "assessment":"floor：知道有三个投影矩阵，能说出 Q 是查询；ceiling：说不出为什么不能共享一个矩阵；misconception：以为 Q/K/V 是三种不同的输入，而不是同一输入的三次投影；build from：floor 就在『同一输入、三种投影』这一句"},
  {"strand":"softmax 的作用",
   "assessment":"floor：能算 softmax；ceiling：不清楚为什么要归一化；misconception：无；build from：直接可用，节点可压缩"}
]
JSON
```

## 什么时候停

三个信号满足任一个就停：

1. 每条 strand 都有了 floor/ceiling/misconception，**足够画计划**。
2. 用户明显不耐烦（"你到底要问多少题"）——立刻转计划，把剩下的探针改成教学中的检查。
3. 已经问了 8 题还没收敛——说明 strand 拆错了，回去重拆。

## 探针阶段的产物

一句话：**一张"他已经站在哪里"的地图**。不是成绩单，不要给用户打分或评价"你基础一般"。评估的措辞要具体到可操作（"你说不出为什么不能共享投影"），不要贴标签（"你对注意力理解不深"）。
