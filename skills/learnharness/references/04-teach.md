# 04 · 教学循环（teach）

每一轮只做一件事：**推进一个推理步，然后验证它真的被理解了。**

## 三种动作，一个节奏

| 动作 | 形式 | 何时用 |
|---|---|---|
| **预测**（predict） | 开放题：不给选项，问"你觉得会怎样" | 引入一个新推理步之前 |
| **解释** | 你讲这一步 | 预测之后 |
| **检查**（check） | 选择题，答完才揭示 | 解释之后 |

节奏是：预测 → 解释 → 检查 →（过）下一节点 /（不过）回到解释。

## 预测：先让他暴露模型

问法要具体到能判断对错，但**不要给选项**——选项会把开放预测变成猜测。

| 差 | 好 |
|---|---|
| "你觉得 softmax 有什么用？" | "如果注意力分数不归一化，直接加权求和，会发生什么？" |
| "你对多头了解吗？" | "8 个头各 64 维，和 1 个头 512 维，你觉得差别在哪？" |

预测**不判对错**，只用来定位他的模型。他猜错了是好事——猜错的地方就是下一步要解释的地方。

预测的回答要引用回去："你刚才说会变成 NaN——对了一半，实际会变成没有竞争性的平均。"

## 解释：只讲这一步，讲完停

三条硬约束：

1. **只讲一个推理步。** 不要顺手把下一步也讲了。多讲的每一步都在稀释这一步。
2. **讲完就停。** 不要"顺便总结一下"。总结会把推理链压成结论，而结论是最容易被复述、最不容易被理解的东西。
3. **每一步都要落在他已经接受的东西上。** 如果他接受了 A、B，你要让他看见"从 A 和 B 到 C 只有一步，而且没有别的可能"。

好的解释让人产生"这不显然吗"，而不是"哦原来如此"。

## 检查：答完才揭示

用选择题（`commit` + `ask_user_question`）。**选项里绝不能暗示哪个对**：

- 选项写成裸断言，长度接近
- 不加 `description`
- 不要"以上都对"/"以上都不对"
- 不要把正确选项写得比干扰项更细、更长、更谨慎

答完之后才给解释。答错时**先定位断点，再决定要不要给答案**：

> "你选了这个，说明你把 Q 和 K 当成两种不同的输入了——它们其实是同一个输入的三次投影。这个区别是关键。"

## 检查不过：回到这一步，不要往下走

这是整套方法唯一不能妥协的规则。

- 不通过 → **重讲这一步**，换一个切入点（用他刚犯的错作为新的起点），然后再检查一次。
- 连续两次不过 → 说明这个节点的前置有缺口，**往后退一个节点**，而不是把这个节点讲得更细。
- 通过 → `visit <nodeId>`，进入下一个节点。

"先往下走，回头再补"在这套方法里等于放弃——后面每个节点都要用这个缺口。

## 处理三种危险信号

| 信号 | 真实含义 | 怎么办 |
|---|---|---|
| "我大概懂了" | 懂的是措辞，不是结构 | 立刻出应用题验证；不通过就重讲 |
| 学生开始复述你的原话 | 他把这当成要背的文本 | 换场景："那如果换成 X，你说的这个还成立吗？" |
| 学生连续答对但说不出思路 | 可能是模式匹配 | 追问"你是怎么排除另外两个的" |

## 用他的话回敬他

学生用模糊措辞时（"差不多就是加权吧"），把它**变成术语再还给他**：

> "你说的'加权'，就是 attention 里的权重——它的来源是 Q 和 K 的点积。所以你其实已经说出了核心，只差一步：权重不是给的，是算出来的。"

这比直接给定义有效得多，因为它证明了**他自己已经在正确的路上**。

## 一轮的收尾

每轮结束时，用一句话说清"我们刚走到了哪、下一步是什么"。不要长篇总结。

位置信息从状态里取，不要凭记忆：

```bash
node ~/.dsh/skills/learnharness/scripts/lh.mjs status
```
